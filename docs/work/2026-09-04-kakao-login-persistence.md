앞선 설치 앱 진단에서 카카오 로그인 직후 member.kakaogames.com 콜백이 로딩 상태로 남았다. 당시 SDK 임시 sessionStorage 항목이 없었고, 쿠키·UA를 그대로 두고 시작 경로부터 다시 진입하자 완료됐다. 런처의 백그라운드 검증 창 종료와 수동 로그인 창 재생성 사이의 상태 전달을 별도 확인할 필요가 있다. 이 현상에 대한 제품 수정은 하지 않았다.

## 결론과 최소 수정 후보

이번에 재현한 실패는 **새 인증 쿠키가 디스크에 저장되기 전에 프로세스가 강제로 종료되는 문제**와 일치하며, flush 대조군에서 예방됐다. 서버 내부의 토큰 무효화 구현이나 과거 업데이트 두 건을 직접 관측한 것은 아니므로 그 내부 정책까지 단정하지 않는다.

Electron 공식 문서는 쿠키를 즉시 디스크에 기록하지 않고 보통 30초 또는 512회 작업 후 기록하며, `cookies.flushStore()`는 미기록 데이터를 디스크에 쓰고 완료 Promise를 반환한다고 설명한다: https://www.electronjs.org/docs/latest/api/cookies#cookiesflushstore

현재 `UpdateInstallHandler`는 PowerShell 정리 후 바로 `autoUpdater.quitAndInstall()`을 호출하며 카카오 세션 flush가 없다. 설치 프로그램은 taskkill /F를 사용한다. 일반 `before-quit`의 async 리스너도 `preventDefault()`로 종료를 지연하지 않는다.

우선 검토할 최소 변경은 **명시적 업데이트 설치를 시작하기 전에 카카오 세션의 flush 완료를 기다리는 것**이다. UA 고정을 이번 쿠키 저장 문제의 해결책으로 취급하지 않는다. 설치 파일을 사용자가 직접 실행하는 경로, 일반 강제 종료, 종료 시 자동 설치까지 보장하려면 별도 범위 검토가 필요하다. flush 실패 시 설치 진행 여부, 진행 중 인증 요청과의 경합, 중복 설치 요청 처리는 구현 사전 검토 대상이다.

이번 승인은 브랜치 준비와 진단 테스트까지이며 제품 수정·커밋·푸시·머지는 수행하지 않았다. 실제 설치 업데이트 전후 검증은 남아 있다.

## 증거

로컬 임시 디렉터리 `ua-investigation-1788510450478` 아래 `evidence/network-master-sanitized.jsonl`에 이번 소스 빌드 테스트의 요청 1,016건을 기록했다. `evidence/results-master.json`은 판정·종료·flush 이벤트 요약이다. `injection-master.js`, `launch-master.cjs`, `inspect.cjs`는 임시 진단 도구이며 제품 빌드나 커밋 대상이 아니다. 실제 프로필·일반 앱 로그는 공유용 증거가 아니다.

최종 진단 앱 PID 63804 및 확인된 자식 프로세스의 종료를 확인했다. UA 변경은 종료된 진단 프로세스에만 적용됐고 제품 코드에는 반영하지 않았다. 저장소에는 이 조사 문서만 신규로 추가했으며 이전 작업 문서는 그대로 보존한다.

## 구현 승인과 계획 — 2026-09-04

위 조사 단계 이후 사용자가 “일단 개선 진행해줘”로 **쿠키 저장 → 정상 종료 → 설치기의 종료 대기 → 시간 초과 시 기존 종료 처리** 개선을 승인했다. 앞 절의 제품 수정 미승인 상태는 조사 당시 기록이다. 현재 구현 범위는 다음과 같다.

- 종료 단계 소유자는 작은 `app-shutdown` 모듈이다. 명시 설치와 `before-quit`는 진행 중 준비 Promise를 공유한다. 카카오 영구 파티션 쿠키 저장을 최대 10초 기다린 뒤 기존 서비스 정리와 PowerShell 정리를 실행한다. 서비스 정리는 최대 5초 기다리고 지연·실패를 기록한 뒤 정상 종료를 계속한다.
- 쿠키 저장 실패·시간 초과 시 설치/종료를 중단하고 안내한다. 서비스 정리 전에 실패하므로 재시도 가능하다. 정상 종료 중복 이벤트는 준비를 중복 실행하지 않는다. X 버튼의 트레이 최소화 동작은 유지한다.
- 명시 설치는 다운로드 완료 상태에서 준비 완료 후 `quitAndInstall`한다. 설치기 실행 오류가 발생하면 자동 설치 재시도를 끄고 안내 후 정상 종료한다. 서비스가 정리된 앱을 계속 사용하도록 남기지 않는다.
- 설치기의 `customInit/customUnInit` 즉시 강제 종료를 제거한다. 기본 실행 여부 확인 앞에서 약 15초 동안 종료를 기다린 뒤 기존 electron-builder 종료 처리를 사용한다. 기본 처리 자체의 추가 대기 시간은 별도이다. 사용자 직접 설치/제거는 앱에 정상 종료 요청을 보내는 새 프로토콜을 추가하지 않으며 기존 종료 확인/처리를 보존한다.
- UA, 로그인 DOM, 쿠키 값·속성, 설정 스키마, IPC/EventBus 계약, 의존성과 사용자 데이터 삭제/UAC 정책은 변경하지 않는다. `app:relaunch`의 `app.exit`는 별도 경로로 이번 범위에서 제외한다.

영향 범위는 Windows 앱 종료와 업데이트 설치 순서이다. 진행 중 인증의 모든 시점이나 외부 강제 종료까지 보장하지 않는다. 처음 수정 버전으로 전환할 때는 구버전 앱이 실행 중이므로 새 앱 측 저장 처리를 소급 적용할 수 없다.

### 설계 검토

별도 읽기 전용 리뷰 `update_shutdown_review`가 기존 NSIS 기본 처리도 PowerShell `Stop-Process`를 사용함을 확인했다. 단순 커스텀 kill 제거만으로는 부족하며 앱 측 준비 완료 대기가 핵심이라는 결론이다. 단일 사전 flush 이후 정상 종료에 맡기는 최소 설계를 수용했고, 설치 실패 후 정리된 앱 방치 방지와 NSIS `getProcessInfo.nsh`/`pid` 선언 보존을 요구했다.

### 구현 및 QA 결과

- `app-shutdown.ts`가 로그인 쿠키 저장, 기존 서비스·PowerShell 정리와 비동기 종료 대기를 소유한다. 기존 `window-all-closed`의 중복 정리를 제거했다. 설정을 변경하거나 쿠키 값을 읽어서 로그에 기록하지 않는다.
- `UpdateInstallHandler`는 다운로드 완료 및 중복 요청을 확인하고 준비 완료 뒤 설치기를 시작한다. 저장 실패는 설치 화면의 다운로드 완료 상태를 유지하고 오류 안내 후 재시도 가능하다. 설치기 실행 오류는 서비스 정리 이후이므로 안내 후 정상 종료한다.
- 기존 코드에서 새 설치 테스트 5개가 실패함을 먼저 확인했고 수정 후 통과했다. 최종 `UpdateHandler`, `app-shutdown`, 카카오 DOM·전환 오류·표시 정책 5파일 **46개 테스트 통과**. 대상 ESLint, `git diff --check`, `build:check` 통과. 기존 Vite 500kB 청크 경고만 남는다.
- electron-builder NSIS 패키징/컴파일을 완료했다. 캐시된 node_modules 버전 표시는 43.1.1이지만 `electronDist`에는 별도 확보한 실제 43.4.1 런타임을 지정했다. 의존성·lockfile 변경은 없다. 패키지는 `.tmp/shutdown-qa-package`의 로컬 QA 산출물이며 배포하지 않았다.

NSIS는 제품의 `customCheckAppRunning`과 현재 electron-builder 기본 매크로를 그대로 포함한 별도 무설치 harness로 확인했다. 고유 이름을 가진 소유 테스트 프로세스만 대상으로 했으며 레지스트리/사용자 설치 디렉터리는 변경하지 않았다. 자연 종료는 프로세스 exit 0, harness 종료까지 13.0초; 계속 남은 프로세스는 대기 후 기존 종료 처리로 exit 1, harness 완료까지 28.8초였다.
