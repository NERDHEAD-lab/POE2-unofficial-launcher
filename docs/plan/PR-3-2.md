## 배경

PR-3 의 BuildListView 는 PoB 원본의 1:1 포팅이라 PoB 의 한계 (단일 패널, 폴더 진입 시 빌드 가려짐) 가 그대로 따라왔다. 사용자 피드백 (2026-05-26):

> "폴더 UI 도 기존 스타일 말고 탐색기처럼 왼쪽에는 폴더 오른쪽에는 클릭한 폴더 위치의 빌드들로 표시해줄래?
> AI 챗 UI 구조처럼 왼쪽에 메뉴가 있고 채팅 목록이 있으면 눌렀을 때 오른쪽에 표시되고 좌상단에 메뉴버튼으로 채팅 목록 부분을 접을 수 있는 것 처럼 개선이 되면 좋을 것 같아"

§4.3 의 "1:1 포팅 원칙" 과 충돌하지 않음 — **컨트롤은 모두 유지**, 배치만 launcher 의 UX 에 맞게 재구성.

## 목표

비공식 런처 한정으로 **2-pane 탐색기 UX + ChatGPT sidebar 스타일 접기**. 빌드 새로 만들기 시 자동 저장 흐름 추가.

🎯 본 PR 머지 후 BuildListView 가 launcher 의 own UX 로 완성. 마일스톤 변경 없음 (여전히 M1).

## 3. 자동 저장 흐름

### 3.1 새 빌드 (fileName 없음)

1. 진입 시 우측 패널이 빈 BuildEditView. `dirty` state = false.
2. 사용자가 입력하면 `dirty = true`.
3. 사이드바의 다른 빌드를 클릭하거나 + 새 빌드를 누름 → `dirty` 검사:
   - **자동 저장 ON** (사이드바 하단 체크박스): `Unnamed build (N).xml` 로 자동 저장 + 이동. N 은 현재 폴더 안에서 충돌하지 않는 첫 번째 정수.
   - **자동 저장 OFF**: 모달 다이얼로그.
     - 제목: "저장하지 않은 변경 사항"
     - 본문: "이 빌드를 'Unnamed build (N)' 로 저장하시겠습니까?"
     - 버튼: `저장` / `삭제` / `취소`
       - 저장 → `Unnamed build (N).xml` 로 저장 후 이동
       - 삭제 → 변경 버림 후 이동
       - 취소 → 이동 자체 취소 (다이얼로그만 닫힘)

### 3.2 기존 빌드 (fileName 있음)

PR-3 범위 외 (PR-5 의 Lua 연동 영역). 본 PR 에선 신규 빌드 자동 저장만 처리 + 인터페이스만 준비.

### 3.3 창 닫기 (X 버튼)

- `dirty && 자동 저장 OFF`: 동일 다이얼로그 표시. `취소` 시 창 닫기 취소.
- `dirty && 자동 저장 ON`: 자동 저장 후 닫기.
- `!dirty`: 즉시 닫기.

### 3.4 넘버링 (`Unnamed build (N)`)

PoB 원본 [BuildList.lua](file:///mnt/d/project_poe2/PathOfBuilding-PoE2-KR/src/Modules/BuildList.lua) 의 `Unnamed build` 패턴 따름. 충돌 시 `(2)`, `(3)` ... 추가. `Unnamed build` 자체가 비어있으면 첫 빌드는 `Unnamed build`, 두 번째부터 `(2)` 부터 시작.

i18n: ko `Unnamed build`, en `Unnamed build` (동일). ko 의 인게임 용어 정합은 후순위 백로그 §5.2.

### 4.8 builds IPC — 변경 없음

PR-3 의 5개 핸들러 그대로 재사용. 자동 저장은 `builds:copy` 가 아니라 신규 핸들러가 필요 — **PR-5 의 Lua 세션이 실제 저장을 담당**. 본 PR 에선 fs 로 빈 XML stub 생성 (`<PathOfBuilding2></PathOfBuilding2>` 정도) 으로 자리표시.

새 핸들러 `builds:save-stub`:

- 입력: `{ subPath, fileName }`
- 동작: 빈 `<PathOfBuilding2 />` XML 을 `<subPath>/<fileName>.xml` 에 write (이미 존재하면 error)
- 출력: `BuildsMutationResult`

PR-5 에서 이 핸들러는 제거되고 실제 PoB Lua 가 dump 한 XML 로 교체됨.

## 5. 검증 시나리오

1. POB i18n 버튼 → 새 창. 좌측 사이드바 + 우측 빈 새 빌드 화면.
2. 사이드바 ☰ 클릭 → 사이드바 접힘. 다시 클릭 → 펼침.
3. `▸ 📁 Builds` 클릭 → 펼침 + 안의 폴더/빌드 들여쓰기로 표시.
4. `Imported Build` 클릭 → 우측 패널에 BuildEditView (PR-5 placeholder).
5. - 새 빌드 → 우측 패널 빈 화면. 이름 input 에 "Test" 입력 (dirty = true).
6. 사이드바의 다른 빌드 클릭 → 자동 저장 체크 OFF 면 다이얼로그 띄움. "저장" → `Unnamed build (3).xml` 생성 (1, 2 이미 있으면). "삭제" → 변경 버림. "취소" → 다이얼로그만 닫힘.
7. 자동 저장 체크 ON → 6번에서 다이얼로그 없이 자동 저장 + 이동.
8. 자동 저장 체크 상태는 창 닫고 다시 열어도 유지 (electron-store).
9. 사이드바 폭은 280px 고정.
10. 검색 input → 트리/목록 모두 필터링.
11. 정렬 셀렉터 → name / class / lastEdited / level 동작.
12. F2 키 → 선택 항목 이름 변경 prompt.
13. Delete 키 → 선택 항목 삭제 확인 모달.
14. 빌드 파일 또는 폴더를 다른 폴더에 Drag & Drop → 해당 위치로 이동.
15. **Lua 프로세스 spawn 0회** 유지.

### 9.5 추가 확인 완료 항목

아래 항목은 사용자 확인 완료. 후속 세션에서 재질문하지 않는다.

- **패키지 분리 (모노레포 분리) 는 몇 번째 PR 에서 진행할 예정인가?** ✅ 확정: PR-10 머지로 M7 BETA 출시 후보를 달성하고, 패키지 분리는 그 직후 최종 PR-N 에서 진행한다. 중간 PR 에는 포함하지 않는다. PR-N 범위는 npm workspaces 패키지 분리 + `pob-ui` 독립 빌드 검증까지이며, pnpm 마이그레이션은 후순위 별도 트랙.
