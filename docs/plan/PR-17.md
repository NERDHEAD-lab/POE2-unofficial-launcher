# PR-17: Tree resource caching and rendering performance

> 상위 문서: [../pob-handoff.md](../pob-handoff.md)

## 목표

Tree 탭이 사용자가 보기에 단계별로 늦게 로딩되는 문제를 줄인다. wrapper window open, Tree 탭 warm return, build switch 경로를 구분해 측정하고, tree layout/resource/DDS decode 결과를 캐싱 또는 프리워밍한다.

계획 문서 관리 규칙에 따라 이 문서는 코드 커밋에 포함하지 않고 unstaged 상태로 둔다.

## Context Notes

- [x] 기존 Tree 탭은 `PassiveTreeView` mount 시 `treeSnapshot`/`treeMetadata` 를 호출하고, 같은 effect 안에서 DDS/PNG 리소스를 매번 수집/로드했다. 탭 전환 unmount 후 warm return 에서 image state 가 사라지는 것이 지연 원인이다.
- [x] `passiveTreeResourceCache.ts` 는 snapshot/metadata 요청, resource manifest, DDS/PNG load, canvas draw stage 를 `pob:treePerf` localStorage flag 기반 개발 로그로 분리 계측한다. test fixture 는 cold/warm/build-switch scenario classification 과 cache key 분리를 고정한다.
- [x] static resource cache key 는 normalized vault path, tree version, asset fingerprint 로 구성한다. locale, hover/search/allocated state 는 resource key 에 포함하지 않고, renderer size/zoom/devicePixelRatio 영향은 projection/canvas draw 단계로 분리한다.
- [x] `BuildEditView` 는 ready 상태에서 active tab 이 Tree 가 아니면 best-effort prewarm 을 실행한다. prewarm 실패는 기존 Tree lazy load fallback 을 막지 않는다.
- [x] DDS decode 는 dependency 없이 파일 단위 Promise fan-out 을 유지한다. worker 전환은 decoded canvas ownership/transfer 와 추가 worker contract 가 필요하므로 현재 PR 에서는 cache reuse 로 제한한다.

## Decisions / Risks

- [x] DDS worker 또는 새 dependency 는 추가하지 않았다. 현재 파일 단위 Promise fan-out/cache 로 충분히 병렬화되고, dependency 필요 시 사용자 확인 원칙을 유지한다.
- [x] `treeSnapshot` 자체는 build-specific state 이므로 cache 하지 않는다. build switch 에서 동일 tree version static resource 만 재사용하고 allocated/search/hover/path preview 는 active snapshot/state 로 갱신한다.
