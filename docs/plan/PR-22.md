# PR-22: Passive Tree resource/cache/render optimization

> 상위 문서: [../pob-handoff.md](../pob-handoff.md)
> 원천 항목: [PR-20](PR-20.md)에서 이관한 Passive Tree AppData cache / static render layer 최적화
> 선행 PR: [PR-21](PR-21.md)
> 후속 PR: 현재 없음

## Goal

PR-20에서 계측한 Passive Tree latency를 바탕으로 Tree resource cache와 rendering pipeline을 최적화한다. AppData/userData persistent asset cache, static/dynamic layer 분리, allocation/path overlay fast path, drag/pan 중 redraw 최소화를 다룬다.
PR-21의 post-PR20 issue follow-up 범위와 분리해, 이 문서는 Tree 최적화 전용 PR로 유지한다.

계획 문서 관리 규칙에 따라 이 문서는 코드 커밋에 포함하지 않고 unstaged 상태로 둔다.

### PR-22.2 AppData Passive Tree asset/resource cache

- [ ] 현재 renderer in-memory `ddsFileCache` / `pngImageCache` 구조와 `assetFingerprint` 생성을 재검토한다.
- [ ] `app.getPath("userData")` 하위 전용 cache directory를 설계한다.
- [ ] cache key는 `schemaVersion + game + PoE2 data version + RePoE/GGPK baseline + vault/treeVersion + asset fingerprint`를 기본으로 한다.
- [ ] build hash가 바뀌지 않아도 PoE2 data version, RePoE/GGPK baseline, vault treeVersion, asset fingerprint가 바뀌면 miss 처리한다.
- [ ] raw asset bytes cache와 derived raster cache 중 실제 Electron renderer/main boundary에 맞는 방식을 선택한다.
- [ ] cache hit/miss/fallback 로그를 `pob:treePerf` opt-in 로그에 포함한다.

### PR-22.3 Static tree payload and build overlay contract

- [ ] Tree snapshot에서 static geometry/resource fields와 build-specific allocation/path/dependency/preview fields를 분리할 수 있는 shared contract를 설계한다.
- [ ] class/ascendancy, treeVersion, vault generation 변경 시 static payload invalidate 규칙을 확정한다.
- [ ] allocation/deallocation/import/build switch 시 dynamic overlay만 갱신하는 fast path를 설계한다.
- [ ] 기존 full snapshot/full render fallback을 유지한다.

### PR-22.4 Canvas multi-layer renderer

- [ ] WebGL/shader rewrite는 1차 범위에서 제외하고 기존 Canvas 2D renderer를 layer 분리한다.

- [ ] drag/pan 중에는 cached layer bitmap을 transform으로 이동하고, drag end 또는 throttled frame에서 필요한 layer만 redraw한다.
- [ ] tooltip hit testing, hover reset, keyboard/focus 상태가 layer 분리 후에도 stale state를 남기지 않게 한다.

## Context Notes

- PR-20 agent 로그 기준 최초 주 병목은 Lua snapshot/metadata보다 renderer `translate-tree`였고, PR-20에서 translation cache와 Tree keep-alive를 먼저 적용했다.
- `packages/pob-ui/src/views/passiveTreeResourceCache.ts`는 현재 renderer process in-memory cache를 사용한다. AppData persistent cache는 아직 없다.
- `buildPassiveTreeResourceManifest()`는 snapshot node metadata에서 DDS/PNG resource manifest와 `assetFingerprint`를 만든다. 이 값은 PR-22 cache key의 핵심 후보이다.
- HTMLCanvasElement/HTMLImageElement 자체는 AppData에 직접 저장할 수 없으므로 raw asset bytes 또는 derived raster blob/cache boundary를 별도 설계해야 한다.
- Tree layer 분리는 shader/WebGL 재작성보다 기존 Canvas 2D renderer 유지가 1차 방향이다.

## Decisions / Risks

- 게임 데이터와 PoB vault asset baseline이 바뀌면 build hash가 같아도 persistent cache를 miss 처리한다.
- cache miss, cache read 실패, schema mismatch에서는 기존 full Lua snapshot/resource load/render fallback을 유지한다.
- static payload와 dynamic overlay를 분리하더라도 PoB Lua 원본 node id/path/depends/alloc semantics는 유지한다.
- Tree renderer 최적화는 display/performance layer 변경이며, PoB action/input domain을 바꾸지 않는다.
