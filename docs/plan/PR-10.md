## 작업 항목

### 1. Override 레이어 구조

- 새 파일: `src/main/services/pobRepoe/overrides/passiveTreeText.ts`
- 패턴 (plan §5 Phase 5.5 원칙):
  ```ts
  export const passiveTreeTextOverride = {
    enabled: true, // 회귀 시 false 로 한 줄 비활성화
    apply(
      nodeId: string,
      englishName: string,
      englishDescription: string,
    ): {
      name: string;
      description: string;
    } {
      if (!this.enabled)
        return { name: englishName, description: englishDescription };
      const koData = repoeCache.getNode(nodeId);
      return {
        name: koData?.name ?? englishName,
        description: koData?.description ?? englishDescription,
      };
    },
  };
  ```
- 호출 위치: PR-6.1 Tree 탭의 노드 렌더링 + 툴팁

### 2. PoB Lua 측 변경 없음

- **원칙 (plan §5 Phase 5.5)**: PoB 소스에 patch 만들지 않음
- ipc_bridge.lua 는 영문 ID 만 반환 (이미 PR-4/PR-5 에서 그렇게 동작)
- Override 는 launcher TS 측에서만 작동

### 3. RePoE 트리 데이터 구조 매핑

- `passive_skill_trees/Default.json` (Korean) 의 노드 구조 확인 (PR-7 에서 다운로드됨)
- nodeId 매칭 규칙: PoB 의 nodeId 와 RePoE 의 nodeId 가 동일하다는 가정 (PR-7 baseline 시점에 확인 필요)
- 불일치 시 매핑 테이블 필요 (별도 작업)

### 4. UI 통합

- PR-6.1 Tree 탭의 노드 호버 툴팁:
  - 이전 (PR-6.1, PR-7 직후): 영문 노드명 + Translator 즉석 호출
  - 본 PR: `passiveTreeTextOverride.apply()` 거쳐 일관된 매핑
- BuildEditView 의 Calcs/Items 탭이 트리 노드 텍스트 참조하는 곳이 있다면 동일 override 적용 (단, 본 PR 은 Tree 탭만)

### 5. vitest

- 새 파일: `src/main/services/pobRepoe/overrides/passiveTreeText.test.ts`
- 케이스:
  - 캐시에 있는 노드 → 한국어 반환
  - 캐시에 없는 노드 → 영문 fallback
  - enabled=false → 항상 영문
  - RePoE 캐시 미설치 (offline) → 영문 fallback

- **Phase 5.5 원칙**:
